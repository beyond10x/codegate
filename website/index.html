01 / Architecture

A small core with a clear boundary.

Language bindings supply observations. Shared analyses and checkers operate on an admitted intermediate representation (IR), independent of language syntax.

What ships today

The 0.2.1 CLI evaluates normalized JSON offline. The Rust library also collects selected Rust, Go and Java source bytes and static build configuration, derives content identities, and validates imported rich facts. Declaration extraction, source collection commands and semantic navigation remain planned work. Language labels take the same shared evaluation path, with incomplete evidence reported explicitly.

01

Measure destinations

Fan-out counts distinct resolved destinations for the selected dependency kind. Repeated imports count once. Self-edges count too.

02

Keep the evidence

A forbidden dependency produces a finding for each observed edge, with its ID and endpoints. Separate occurrences remain traceable.

03

Preserve uncertainty

Incomplete facts never become a passing check or a measured zero. Reports distinguish partial, unsupported and failed collection.

02 / Get started

Run an offline check.

The example below has two units and one runtime dependency from core to io.

  1. Install Codegate 0.2.1

    Download the x86-64 Linux archive and checksum list from the 0.2.1 release. The prebuilt binary targets GNU/Linux.

    curl -fLO https://github.com/beyond10x/codegate/releases/download/0.2.1/codegate-0.2.1-x86_64-unknown-linux-gnu.tar.gz
curl -fLO https://github.com/beyond10x/codegate/releases/download/0.2.1/SHA256SUMS
sha256sum --check --ignore-missing SHA256SUMS
tar -xzf codegate-0.2.1-x86_64-unknown-linux-gnu.tar.gz
./codegate --version

    Put the extracted codegate binary on your PATH, or use ./codegate in the commands below.

    Build from source instead

    Install the pinned Rust 1.98.1 toolchain. Evaluating facts needs no ESS or AEP installation.

    git clone --branch 0.2.1 https://github.com/beyond10x/codegate.git
cd codegate
cargo build --locked --release --bin codegate
./target/release/codegate --version

    Use ./target/release/codegate in place of codegate below.

  2. Save the facts

    Copy this complete document to facts.json. Unit IDs are local to this snapshot; every resolved edge points to a listed unit.

  3. Choose a policy

    Save this as policy.json. It selects runtime edges and allows every dependency. Source and configuration IDs must match the facts.

  4. Evaluate, then try a violation

    codegate evaluate --facts facts.json --policy policy.json
codegate evaluate --facts facts.json --policy policy.json --out report.json

    The report says Pass, the process exits 0, and fan-out is 1 for core and 0 for io. The optional --out writes the report to a file instead of stdout.

    Replace the policy’s empty forbidden array with this rule and run again:

    "forbidden": [
  { "source": "core", "target": "io", "kind": "Runtime" }
]

    Now the verdict is Fail, the process exits 1, and the finding identifies edge e1. Its fan-out remains 1.

03 / Results and CI

A verdict carries its coverage.

Check both the result and the available evidence. The CLI exit status lets a CI job distinguish a complete policy failure from an evaluation that could not complete.

Results for an admitted snapshot

A witnessed violation with partial coverage remains a Fail, while exit 2 preserves the incomplete evidence. Partial, unsupported and failed results include a coverage diagnostic.

Invalid graph or policy

Semantic admission failures return an Error report, diagnostics and empty metrics/findings, with exit 2. Examples include duplicate unit IDs, dangling references and mismatched source IDs.

Invalid JSON document

Malformed JSON, duplicate object keys, unknown fields or types, and exceeded input limits produce a stderr diagnostic and exit 2, without an evaluation report.

04 / Fact contract

Explicit values. Shared meaning.

The dependency formats are experimental. Version 0.2.1 implements this dependency slice; it does not promise a stable universal IR yet.

Versioned identifiers
PurposeIdentifier
Factscodegate-dependency-facts/0.1
Policycodegate-dependency-policy/0.1
Reportcodegate-dependency-report/0.1
Metricdependency.unique-fan-out/1
Checkerdependency.forbidden-edge/1

Graph identities

Unit and edge IDs are nonempty and unique within their respective lists. Every edge source must exist. Each edge has exactly one nonempty resolved target or unresolved_target; a resolved target must exist.

Dependency kinds

Edges use Runtime, Build or Test. The policy selects one kind. All forbidden rules must use that kind and refer to existing units; duplicate rules are refused.

Coverage obligations

All statuses require the complete selected unit inventory. Complete has no gaps or unresolved targets. Partial names at least one gap. Unsupported and Failed name a gap and contain no edges.

Identity and bounds

Source and configuration IDs are producer assertions compared for equality; they do not verify source bytes or authenticity. Each document is limited to 4 MiB, with at most 10,000 units and 50,000 edges per snapshot.

Reports copy the applied policy, echo source/configuration IDs, and include the metric and checker IDs. Unit metrics sort by unit ID; findings sort by edge ID. The evaluator keeps behavior independent of input ordering and language labels.
